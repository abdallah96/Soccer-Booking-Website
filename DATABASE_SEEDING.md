# Database Seeding Guide\n\nThis guide will help you populate your Supabase database with test data.\n\n## Overview\n\nYou have **two methods** to seed your database:\n\n1. **SQL Method** (Recommended - Easiest) ⭐\n2. **TypeScript Script Method** (For automation)\n\n---\n\n## Method 1: SQL (Recommended - Easiest) ⭐\n\nThis is the fastest and most straightforward method.\n\n### Step 1: Create Database Tables\n\n1. Go to your Supabase dashboard\n2. Open **SQL Editor**\n3. Create a new query\n4. Copy the contents of `src/lib/db/schema.sql`\n5. Paste it into the SQL editor\n6. Click **Execute** or press `Ctrl+Enter` / `Cmd+Enter`\n\nWait for the tables to be created successfully.\n\n### Step 2: Seed Sample Data\n\n1. In the same **SQL Editor**, create a new query\n2. Copy the contents of `src/lib/db/seed.sql`\n3. Paste it into the SQL editor\n4. Click **Execute** or press `Ctrl+Enter` / `Cmd+Enter`\n\nYour database is now populated with:\n- ✅ 4 users (1 admin + 3 regular users)\n- ✅ 5 football fields\n- ✅ Time slots for next 30 days\n- ✅ 4 sample bookings with different statuses\n\n---\n\n## Method 2: TypeScript Script Method\n\nIf you prefer automation or need to seed regularly.\n\n### Prerequisites\n\nMake sure you have `ts-node` installed:\n\n```bash\nnpm install -D ts-node @types/node\n```\n\n### Step 1: Set Up Environment Variables\n\nCreate `.env.local` file in the project root:\n\n```bash\nNEXT_PUBLIC_SUPABASE_URL=your_supabase_url\nNEXT_PUBLIC_SUPABASE_ANON_KEY=your_supabase_anon_key\nSUPABASE_SERVICE_ROLE_KEY=your_service_role_key\nJWT_SECRET=your_jwt_secret_key\n```\n\n**Important:** Use your `SUPABASE_SERVICE_ROLE_KEY`, not the anon key. You can find this in:\n- Supabase Dashboard → Settings → API\n- Under \"service_role\" (Secret)\n\n### Step 2: Run Seed Script\n\n```bash\nnpm run seed\n```\n\nOr directly with npx:\n\n```bash\nnpx ts-node scripts/seed.ts\n```\n\nThe script will:\n1. Connect to your Supabase database\n2. Create all test users\n3. Add 5 football fields\n4. Generate time slots for 30 days\n5. Create sample bookings\n6. Display the results with emoji indicators\n\n---\n\n## Test Credentials\n\nAfter seeding, you can use these credentials to test:\n\n### Regular Users\n\n```\nEmail: user@test.com\nPassword: test123\nRole: User\n```\n\n```\nEmail: john@example.com\nPassword: (no auto-generated password, you need to set one in login/register)\nRole: User\n```\n\n```\nEmail: marie@example.com\nPassword: (no auto-generated password, you need to set one in login/register)\nRole: User\n```\n\n### Admin User\n\n```\nEmail: admin@sport.sn\nPassword: admin123\nRole: Admin\n```\n\n---\n\n## What Gets Seeded\n\n### Users (4 total)\n\n| Email | Name | Role | Phone |\n|-------|------|------|-------|\n| admin@sport.sn | Admin User | Admin | +221771234567 |\n| user@test.com | Test User | User | +221771234568 |\n| john@example.com | John Doe | User | +221771234569 |\n| marie@example.com | Marie Seck | User | +221771234570 |\n\n### Football Fields (5 total)\n\n1. **Stadium Elite Football Field** - it means the data was already seeded. The `ON CONFLICT DO NOTHING` clause prevents duplicate errors.\n\n### TypeScript Errors\n\nIf you get TypeScript errors when running the seed script:\n\n```bash\nnpm install -D ts-node @types/node typescript\n```\n\n---\n\n## Testing After Seeding\n\n### 1.
